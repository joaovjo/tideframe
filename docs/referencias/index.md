# Referências

Análise dos repositórios em `exemplos/` para extrair padrões de API, arquitetura e DX que o framework deve seguir ou evitar. Cada concept resume um repositório; nenhum código é copiado.

* [Laravel Framework](laravel-framework.md) — Componentes independentes com namespaces próprios.
* [Laravel](laravel.md) — Skeleton de aplicação; convenção sobre configuração.
* [Laravel Docs](laravel-docs.md) — Mapa de features; inventário de batteries.
* [AdonisJS Core](adonisjs-core.md) — Separação por responsabilidade; providers, services e stubs.
* [NestJS](nest.md) — Monorepo real; pacotes independentes, exemplos e integração separados.
* [Elysia](elysia.md) — Pacote único com build próprio; foco em DX e tipos.
* [Hono](hono.md) — Core + adapters; benchmarks e testes de runtime separados.
* [Phoenix](phoenix.md) — Submódulos por domínio; guias e regras para agentes.
* [Vapor](vapor.md) — Multi-target; cada target é uma camada.
* [Django](django.md) — Core monolítico + docs + testes; batteries-included.
* [Angular](angular.md) — Monorepo grande com Bazel; fronteiras de pacotes.
* [Next.js](nextjs.md) — Monorepo JS + Rust; exemplos e docs separados.
* [Nuxt](nuxt.md) — Monorepo com playground e bench.
* [Hummingbird](hummingbird.md) — Swift package multi-target.
* [one-aalam/awesome-bun](one-aalam_awesome-bun.md) — Mapa do ecossistema Bun.
* [oven-sh/awesome-bun](oven-sh_awesome-bun.md) — Mapa do ecossistema Bun.
